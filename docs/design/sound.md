# Sound Design

## Purpose

Sound reinforces a modern, comfortable retro-gaming experience. Interface effects should feel warm, responsive, and subtly nostalgic without copying sounds from consoles, games, or other brands.

## Audio layers

Keep these layers independent:

```text
Game audio
UI audio
Accessibility audio
```

- Game audio is generated by the active emulator core from ROM data and routed to the system output.
- UI audio confirms platform interactions and must never compete with gameplay audio.
- Accessibility audio supports explicit feedback and user preferences.

## Supported files

Initial support targets:

- Game Boy and Game Boy Color games: `.gb` and `.gbc`.
- User-supplied game artwork: `.png`, `.jpg`, and `.webp`.
- UI sound sources: `.wav`.
- Optimized UI sound distribution: `.ogg`.

Compressed game archives and other ROM formats require explicit, validated support from the relevant emulator core or plugin. Unknown files must not be executed or treated as ROMs.

SNES formats such as `.sfc` and `.smc` are a future expansion and require explicit
support from their console and emulator-core plugins.

## UI sound tokens

Use semantic sound tokens instead of binding files directly to components:

| Token | Use | Asset and timing |
| --- | --- |
| `sound.startup` | Confirm that the application is ready for interaction. | One 1-second signature. |
| `sound.focus` | Move focus between navigation items. | Two 40-60 ms variations; 60 ms cooldown. |
| `sound.browse` | Move between consoles or games in the primary carousels. | One dedicated cue; 80 ms cooldown. |
| `sound.select` | Confirm a primary action. | Two 100-140 ms variations. |
| `sound.back` | Return, cancel, or close. | Two 70-100 ms variations. |
| `sound.open` | Open a panel, modal, or menu. | One 120-180 ms cue. |
| `sound.toggle` | Change a setting or switch state. | Separate 60-90 ms on and off assets. |
| `sound.adjust` | Change a slider or stepper value. | Two 35-50 ms variations; 75 ms cooldown. |
| `sound.favorite.add` | Add a game to favorites. | One 150-220 ms positive cue. |
| `sound.favorite.remove` | Remove a game from favorites. | One 150-220 ms release cue. |
| `sound.success` | Confirm a completed operation, such as saving a state. | One 180-260 ms cue. |
| `sound.warning` | Signal a recoverable problem. | One 220-320 ms cue. |
| `sound.error` | Signal a failed action. | One 250-350 ms cue; always paired with visible text. |
| `sound.launch` | Start a game session. | One 350-500 ms transition. |
| `sound.pause` | Pause a game session. | One 150-220 ms cue. |
| `sound.resume` | Resume a game session. | One 150-220 ms cue. |

optimization; source masters are never referenced directly by components.

## Interaction rules

- Trigger effects with meaningful user actions, focus changes, or state transitions.
- Use `sound.browse` only when the selected console or selected game changes.
- Play `sound.startup` only after the primary interface and input handling are ready.
- Alternate `sound.focus`, `sound.select`, `sound.back`, and `sound.adjust` variations deterministically.
- Keep navigation effects short and low-volume.
- Rate-limit repeated directional navigation effects.
- Synchronize effects with the visible interaction or motion.
- Do not use sound as the only confirmation of an action or error.
- Avoid sounds for passive decoration, continuous loading, or every visual animation.
- Do not play effects for text entry, list scrolling, empty states, or a navigation edge.
- Keep UI effects distinct from game audio in mixing, volume, and mute controls.

## Mixing and preferences

- Persist independent `uiAudioVolume`, `gameAudioVolume`, and `uiAudioMuted` preferences.
- Persist `reduceGameAudioDuringUiEffects`, enabled by default.
- Navigation and settings effects never reduce game audio.
- When enabled, `sound.success`, `sound.warning`, `sound.error`, `sound.launch`, `sound.pause`, and `sound.resume` reduce game audio by 5 dB.
- Ducking uses a 30 ms attack and a 250 ms release.
- Overlapping high-priority effects keep ducking active until the final effect completes.
- Missing assets fail silently, preserve the interaction, and emit a structured diagnostic.

## Accessibility and preferences

- Provide independent volume controls for game and UI audio.
- Allow users to mute UI effects without muting game audio.
- Respect a reduced-stimulation preference by reducing nonessential UI effects.
- Pair important sounds with visible, readable feedback.
- Preserve user settings across sessions.
- Persist UI mute and volume in the `user-preferences/global` entry of Electron's
  `preferences.json`; renderer `localStorage` is only a legacy migration source.

## Production briefs

- Tone: soft digital transients, restrained low-end warmth, and sparse reverb.
- Focus: light and tactile, never metallic or intrusive.
- Select: warmer and more resolved than focus.
- Back: descending or releasing, never implying failure.
- Warning: calm but distinct; error: clear without harsh loudness.
- Launch: the most expressive effect, but never louder than gameplay or longer than 500 ms.
- Do not use recognizable console, game, controller, or competitor-platform samples.

## Asset and implementation rules

- Create original UI sounds or use appropriately licensed assets.
- Do not use samples extracted from games, consoles, controllers, or competing platforms.
- Store source assets separately from optimized runtime files.
- Preload only the small set of high-frequency UI effects.
- Audio playback belongs in a dedicated UI-audio service or future `@platform/ui-audio` package, not inside React components.
- Components request semantic tokens; the audio service owns loading, playback, volume, cooldowns, and preference handling.
- The future service exposes a closed `UiSoundToken` contract and `UiAudioService.play(token)`; component code must not reference asset paths directly.

## Validation

- Startup plays once per application launch, not on route change, window focus, or renderer remount.
- Repeated directional input respects the focus cooldown and alternates variations.
- Each semantic interaction requests only its documented token.
- UI mute and UI volume do not affect game audio; game volume remains independent.
- Ducking occurs only for high-priority tokens and restores after overlapping effects finish.
- Warning and error feedback always include visible, readable state communication.
